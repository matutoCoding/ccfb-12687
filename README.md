# 靛蓝工坊 · 扎染蜡染设计与染液渗化仿真系统

浏览器内运行的扎染/蜡染花稿设计与 GPU 染液渗化仿真系统。**TypeScript + WebGL2 + IndexedDB，零后端、零网络依赖，断网可完整开工。**

## 解决的问题

传统打样一缸靛蓝泡两三天，蜡裂冰纹靠运气，客户改色就得重来，耗布耗染料还交不出货。本系统把扎结手法、蜡防、浸染工序全部数字化，在 GPU 上先把效果试明白再下缸。

## 快速开始

```bash
npm install
npm run dev        # 开发
npm run build      # 类型检查 + 生产构建（gzip 后单包约 28KB）
npm run preview    # 预览构建产物
```

要求：支持 WebGL2 与 `EXT_color_buffer_float` 的浏览器（Chrome/Edge 90+、Firefox 90+）。

## 仿真引擎原理（`src/gl/`）

GPU 上以 512×512 浮点 ping-pong 纹理承载状态，状态纹理四通道：

- **R** 累计固着吸色量　**G** 游离染液量　**B** 本道固着量

每道浸染三个 pass：

1. **吸色（UPTAKE）**：染液进入量 = 吸色速率 × 浓度 × 浸染时长 × 进色率（扎结蒙版 × 蜡防蒙版），扎死/封蜡区进色趋近 0。
2. **各向异性毛细扩散（DIFFUSE）**：半拉格朗日回采，沿纤维走向场方向扩散强、垂直方向弱（0.35 倍），疏密场调节孔隙扩散速度，6 次迭代。
3. **氧化固着（FIXATE）**：游离染液按氧化时长固着到纤维；相邻媒染步骤产生促染增益。

合成 pass 用减法混色把吸色深度映射为 sRGB 发色，并叠加织纹明暗、蜡面浮色、退蜡后蜡痕深色圈与薄蜡毛边。

**疵点扫描**：64×64 度量纹理回读 CPU，分块统计梯度（色花）、水平条带突变（色档）、左右镜像不对称（阴阳面）；归因通过比对各道快照在该块的吸色增量，定位贡献最大的责任工序。

**增量重算**：每道结果按工序参数哈希缓存，参数变化时只从第一道失配工序重算，前道走快照恢复，不整缸重跑。

## 数据与离线

全部数据存浏览器 IndexedDB（10 个对象仓库：坯布、项目、配方、染料、仿真结果、订单、排产、分享令牌、批注、设置）。无任何网络请求，刷新/断网不丢数据。导出为 JSON 制作包 + PNG 成品图发给染坊。

## 标定门禁（仿真可信度的关键约束）

每种坯布入库前必须：

1. 标定吸色速率 k 与毛细扩散系数 D；
2. 对散点捆扎、同心环夹板、方格缝缀三幅标准花稿各跑一条仿真试条；
3. 与染坊实拍试条比对，平均色差 ΔE ≤ 6 且晕边宽度误差 ≤ 1.5 mm；
4. 三幅全部通过才置 `approved=true`，未批准坯布在仿真与报价入口被拦截。

## 已知边界

- 织纹识别基于结构张量的启发式估计，精确定量仍需以实拍试条标定结果为准；
- 疵点阈值按当前程序化仿真的度量分布标定（见 `sim-engine.detectDefects`），接入真实染坊数据后应重新校准；
- 分享链接是本机 IndexedDB 令牌，跨设备协作需另行导出 JSON 包。
